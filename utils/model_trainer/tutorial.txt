Fluxo para coletar dados e treinar modelos customizados
=======================================================

1. **Preparar o ambiente de captura**

   ```bash
   pip uninstall opencv-python -y
   pip install opencv-contrib-python
   ```

   Utilize o script `_capture_images.py` para gravar vídeos ou imagens já com as bounding boxes.
   Agora é possível planejar vários objetos na mesma sessão:

   ```bash
   # Ex.: captura de três objetos salvando tudo dentro de datasets/
   python utils/model_trainer/_capture_images.py --base-dir datasets --objects 3

   # Para pular as perguntas interativas de nome:
   python utils/model_trainer/_capture_images.py --base-dir datasets --class-names parafuso porca arruela
   ```

   Durante a captura, `h` avança para o próximo objeto/classe mantendo as mesmas teclas de tracking (`t`), gravação (`s`) e
   salvamento manual (`Space`). Cada objeto é salvo em uma subpasta própria contendo `images/` e `labels/`, por exemplo
   `datasets/parafuso/images` e `datasets/parafuso/labels`. Assim não é mais necessário renomear manualmente a pasta `dataset/`
   entre uma coleta e outra. Ao encerrar a sessão (`q` ou `Esc`), o script gera automaticamente um `data.yaml` dentro de cada
   pasta criada, apontando para as capturas realizadas.

2. **Organizar o dataset para cada modelo**

   O script `_train_model.py` agora pode ser executado diretamente ou importado como função.
   Exemplos:

   ```bash
   # usa o dataset padrão e gera yolo_data/
   python utils/model_trainer/_train_model.py --classes objeto

   # dataset diferente e sem limpar a pasta de saída
   python utils/model_trainer/_train_model.py \
       --dataset datasets/cones \
       --output yolo_data/cones \
       --classes cone \
       --val-ratio 0.1 \
       --no-clean
   ```

   O comando cria `data.yaml` apontando para `images/train`, `images/val` e mapeia as classes fornecidas.

3. **Treinar um ou mais modelos YOLO**

   Para treinar vários modelos de uma vez (por exemplo, três modelos distintos), crie um arquivo YAML com a lista de configurações.
   Você pode usar `utils/model_trainer/sample_training_config.yaml` como ponto de partida
   (note que cada caminho em `dataset:` deve apontar para uma pasta que contenha
   `images/` e `labels/`).

   ```yaml
   # arquivo: training_config.yaml
   models:
     - name: cones
       dataset: datasets/cones
       classes: ["cone"]
       output: yolo_datasets/cones
       train:
         model: yolov8n.pt
         epochs: 100
         imgsz: 640
         batch: 16
     - name: placas
       dataset: datasets/placas
       classes: ["placa_parar", "placa_direita"]
       train:
         model: yolov8s.pt
         epochs: 150
     - name: pedestres
       dataset: datasets/pedestres
       classes: ["pessoa"]
       train:
         model: yolov8n.pt
         epochs: 80
         device: 0
   ```

   Depois execute:

   ```bash
   python utils/model_trainer/train_models.py --config training_config.yaml
   ```

   O script prepara cada dataset, gera seu próprio `data.yaml` e chama o comando `yolo detect train ...` para cada entrada.
   Use `--dry-run` para apenas listar os comandos ou `--skip-train` para pular o treinamento após preparar os dados.

4. **Executar o modelo na aplicação**

   Copie o peso desejado (ex.: `runs/detect/<nome>/weights/best.pt`) para a pasta da aplicação ou defina a variável de ambiente `CUSTOM_OBJECT_MODEL_PATH` apontando para o arquivo.
   A aplicação carregará o modelo customizado junto com o modelo padrão do YOLO.
